A local preview runtime for parallel software work

Every worktree
should be runnable.

Coding agents can create branches faster than teams can preview them. work-containers gives each Git worktree an isolated, dependency-aware Docker Compose environment with stable URLs, structured status, and a clean teardown.

The thesis

The containers already exist.
The coordination layer does not.

Git worktrees solve parallel source control. Docker Compose solves local services. Coding agents solve implementation speed. The missing primitive is a deterministic lifecycle that binds all three together.

01

Agents need previews, not just diffs.

A code change is not understood until the application boots, dependencies resolve, and a human can open the result.

02

Parallel branches need parallel infrastructure.

Shared ports, networks, volumes, and databases turn concurrent work into a queue. Isolation restores actual parallelism.

03

The runtime must be legible to machines.

Structured plans, status, URLs, and failures let Claude, Codex, OpenCode, and CI act without inventing shell commands.

work-containers init proposes a manifest from the codebase. It records what was discovered and how confident the inference is. Destructive lifecycle actions remain explicit.

  • Logical services mapped to Compose services
  • Dependency graph and preview ports
  • Health checks and default preview target
  • Review-first lifecycle hooks

Start locally

From clone to preview
in four commands.

The project is early and intentionally local-first. Link the CLI, initialize a repository, review the generated contract, and start an isolated environment.

1git clone https://github.com/mxrcochxvez/work-containers.git
2cd work-containers && npm link
3cd ~/Projects/my-app && work-containers init
4work-containers up --services web
